# RR/MR preparation and Excel export

Requested outcome: implement the authorized web draft -> original-layout Excel -> physical signatures -> signed-copy upload journey. Manual entry and editable PO prefilling share one form. RR/MR are selected by staff; no invented price threshold, inferred signatures or automatic classification.

Affected roles/journeys: Purchasing and Receiving use their existing record scope to select a PO, prepare and revise documents, export saved revisions and attach a signed image/PDF to a specific revision. Existing PO-document readers retain scoped read/export access. System Administrator gains no procurement access. Entry links are in Purchasing tracking and Receiving history/intake; notifications and procurement decisions are not added.

Dependencies: additive form-series/revision storage; existing private evidence uploader and PO document register; a bundled sanitized template derived from the supplied workbook; a ZIP library for faithful OOXML export; role-scoped APIs and responsive workspace. Manual entry remains linked to a real accessible PO. Sample names and transactions must not ship in exports. Strings are written as text, never formulas. Missing costs remain blank.

Protected behavior: all current PR/PO statuses, cash/credit and provisional online workflows, receiving submission/closure (including damage), Requesting correction/reuse, asset records, audit history and existing document uploads. Preparation, export and signed-copy upload do not constitute receipt, verification of signatures, department handover, financial approval, or Accounting acknowledgment.

Data/contract: a form series belongs to one PO and one type. Saving creates an immutable payload revision and conditionally increments the series version; stale saves return 409. Export reads the exact saved revision and records first export metadata. Signed files append to the existing PO document register with a revision relation and immutable uploader/time. A future edit creates another revision, preserving the old signed file. Every action rechecks scope. Bounded payloads, pagination, no arbitrary file paths, evidence membership/type/existence checks and no workflow writes.

Template rules: retain headings, merges, widths, borders, signature spaces, legal-paper settings and the original two-form sheet arrangement. RR uses 14 physical item rows per copy (the next row is outside the second copy's table); MR uses 9. Word-wrapped descriptions/remarks continue on additional rows/sheets, with whole items kept together where they fit and explicit continuation markers for oversized items. Each sheet carries a revision/page footer. Only item styles are cloned for fitting; static template instructions keep their original size. Printed names remain unsigned. Document numbers are manual until numbering rules are confirmed. RR quantities per invoice/received are distinct; MR quantity represents assignment and is not inferred from PO quantity. No invented credit unit values or allocation of aggregate purchase totals. Decimal line totals round exactly to cents; unresolved totals remain blank.

Verification: isolated schema/prefill/export and route tests before implementation; template structure, text safety, page overflow and absence of sample information; authorization, stale/retry, revision/file ownership and preserved workflow; TypeScript, touched lint, production build; 360/768/1440 px browser fixtures, long content, manual/prefill, save/export/upload errors and unsaved-change protection. No live decisions, seed, cleanup or external messages. Additive migration may be applied to configured local database.

Delivery slices: (1) schema/prefill + template export, (2) scoped revision APIs/storage, (3) web form/entry links, (4) database/build/browser/regression verification. Pending institutional rules remain visible guidance.

## Delivered behavior

`/dashboard/receiving/forms` provides manual drafts and PO prefilling, previews, up to 100 item lines, saved revision history and exact-revision export/upload. Prefilling a PO with more than 100 items stops with guidance to prepare separate documents rather than dropping items. Received/assigned quantities and signature names are never inferred. Credit prices remain unresolved. Each new draft has a stable creation UUID so a repeated first-save request cannot create a second series. Stale edits return 409 and retain the local inputs; Reload document list / Reload saved revisions allow recovery.

`GET /api/receiving/forms` lists scoped POs; `poId` retrieves the PO and paginated document series; `documentId` retrieves paginated revisions on that PO. `POST` SAVE appends a snapshot with its author and increments the series conditionally. ATTACH requires an exported revision, an accessible existing upload and explicit uploader reconciliation confirmation. Reusing a file against another PO/revision/type is rejected. The signed-copy entry is also visible in the existing supporting-document bin. `GET /api/receiving/forms/export?revisionId=...` exports only saved contents and stores first-export metadata, not a procurement event.

Entry links are available in Receiving intake/history, Purchasing tracking details and every scoped PO document panel. Purchasing/Receiving can prepare documents; the other existing document readers can view/export within their current record scope. System Administrator remains excluded.

The source workbook is not bundled with sample transactions. `scripts/prepare-receiving-templates.py` derives the two sample-free templates in `src/templates/receiving/`. The ZIP implementation uses pinned fflate 0.8.3 with no transitive dependencies; the lockfile change adds only this package. The original workbook remains untouched. Next file tracing explicitly includes both templates in the export route's deployment files.
